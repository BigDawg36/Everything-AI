# IMSC Coding Guide QA

## Mission and boundaries
Produce a compact, visually polished, **educational** InterMed SoCal coding reference, not an instruction to bill a particular code. Prioritize clinical accuracy, current source dates, exact procedure context, and a clean black-and-gold IMSC design. If not enough evidence exists for a coding claim, mark it **UNVERIFIED**, explain what is missing, and exclude it from the customer-facing handout until reviewed. Do not present product implantation as automatically establishing eligibility for any procedure code, separate reimbursement, or coverage.

**Mandatory banner for customer-facing or rep-facing output:** "Needs compliance review before use with customers or reps." Do not release or represent approval without documented review by IMSC compliance and qualified coding specialists. Do not provide patient-specific coding advice, legal advice, billing guarantees, or off-label promotion.

## Use when
- Mike asks for an IMSC commonly used nerve wrap or related procedure coding guide or a modification of such a guide.
- He provides two or more coding guides and wants a consolidated reference.
- He asks whether listed codes are current or correctly described, or wants a visually polished PDF or one-page handout.
- He wants clinical-claim, product-indication, reimbursement, or code-year verification before sharing a guide.

## Inputs
1. Target procedures and product families, with exact indications and applicable manufacturer instructions for use (IFU) when product-specific language is present.
2. Code year and effective date; payer and care setting (e.g., Medicare vs commercial; physician/professional vs facility; inpatient vs outpatient) when supplied.
3. The drafts, official documents, coding sheets, or licensed CPT references Mike authorized for review.
4. Audience: internal management, sales representative, physician, facility coding staff, or public.
5. Logo and approved brand assets, if available. Never fabricate an IMSC logo.

If setting/year are missing, assume the current calendar year **only for researching**. Label the applicability as provisional and do not assert code selection without the missing context. If any user-supplied documents are inaccessible, explicitly identify which file is missing.

## Source and verification workflow
1. Identify the **precise performed procedure** from the provided description. Distinguish neuroplasty, repair, graft, conduit/wrap placement, tendon work, and other concurrent work. A device's trade name is not a procedure.
2. Make a working evidence matrix: code or code family, plain-English procedure summary, professional/facility setting, verified status, effective date, source title, direct source link, caveats, and IMSC reviewer decision.
3. Check **authoritative sources in priority order**: current-year properly licensed AMA CPT material for CPT descriptors; CMS HCPCS Level II quarterly files (https://www.cms.gov/medicare/coding-billing/healthcare-common-procedure-system/quarterly-update); current Medicare NCCI policy manual (https://www.cms.gov/medicare/coding-billing/national-correct-coding-initiative-ncci-edits/medicare-ncci-policy-manual); current quarterly Medicare NCCI PTP edits (https://www.cms.gov/medicare/coding-billing/national-correct-coding-initiative-ncci-edits/medicare-ncci-procedure-procedure-ptp-edits); other official Medicare or payer coverage policies as relevant; manufacturer FDA-cleared/approved labeling and IFU for product-specific indications.
4. Record the date actually checked, effective dates, whether a source is payer-specific, and any replacement or deleted code. Explicitly check code validity for the intended service date, not only the date this document is generated.
5. Verify whether NCCI PTP edits, add-on requirements, MUE, bundled services, and payer or site-of-service rules might change whether a code is appropriate. Do not assume a modifier is permitted or payment guaranteed; route ambiguous cases to the facility coder.
6. Keep CPT text licensed: do not copy long, proprietary AMA code descriptors from references or create broad redistributed CPT descriptor tables without appropriate permissions. Short original lay summaries and citations may be used, with source license reviewed. Never treat public availability as a license.
7. Compare provided source guides to one another. Record inconsistencies rather than silently choosing the newer-looking guide. Label unsupported reimbursement rates or product outcome claims **Not verified** and exclude them from distribution.
8. If creating or editing a PDF, inspect all pages after rendering, including text fit, no orphan rows, legibility at print size, functioning links, and absence of unintended prior-draft notes or raw citations in the publication body.

## Layout specification
- Main title: **Commonly Used Nerve Wrap Codes** for nerve-wrap requests, or another grammatically consistent user-specified title.
- Premium IMSC styling: black, restrained champagne gold, clean dividers, generous spacing, readable type and a supplied IMSC logo where authorized. Never add unrelated company product lines or outdated vendors.
- Introductory scope box: intended audience, source year/effective date, payer/site assumptions, and educational limitations.
- Body table fields when evidence supports them: **Procedure context | Code/reference | When it may apply | Important limitations**. Restrict to the truly relevant and verified rows.
- Footer: "Educational reference only. Coding depends on documented services, payer policy, current code sets, and qualified coding review. No reimbursement is guaranteed."
- If the user says to remove sources/review notes from the handout, remove **only their display**. Preserve a distinct internal evidence-and-review file; do not claim the codes are verified without an audit trail.

## Required deliverables
A. **Distribution draft**: copy-ready guide, and PDF when requested, marked pending compliance review.
B. **Internal verification log**: each proposed entry with status **Verified | Needs coder confirmation | Unsupported**; the official source and exact effective date; mismatches between old/new references; and a compact unresolved-items list.
C. **QA summary**: code-year checked, patient/PHI scan, product-claim scan, professional vs facility ambiguity scan, print-layout scan, and named reviewer approval status.

## Privacy, confidentiality and compliance
- Do not request, retain, print, upload, or send patient identifiers, PHI, case-level notes, operative narratives, personally identifying surgeon-level patient data, or confidential account pricing to any third-party skill or service.
- Use only sanitized procedure examples. Never include actual patient scenarios in a generated sample.
- Product claims must be supported by current approved labeling and cleared/approved indications; no outcomes, infection, superiority or cost savings assertions without approved evidence.
- Do not describe anything as FDA approved/cleared unless the specific product and indication are verified.
- **Needs compliance review before use with customers or reps.** Also require a qualified coding professional review for reimbursement and coding statements.

## Writing and approval rules
Direct, warm, professional, no em dashes, light bold, short sentences, no filler. Prefer one page only when readable. Do not bury unresolved coding risks in small footnotes. Before changing user-supplied files, preserve a copy. No publishing, distribution, email, claim submission, or mutation of account data without explicit permission.

## Safe trigger example
"Use IMSC Coding Guide QA to update our nerve wrap coding handout for 2026 using these two approved reference PDFs. Verify against CMS where applicable, distinguish professional vs facility, and deliver a review-ready PDF plus a separate source log."
